## 三、根因分析

### 根因 A（直接根因）：iOS "ping" 污染配对协议

iOS `connectWebSocketWithTimeout()` 在 `resume()` 后立刻发送纯文本 `"ping"`。go-bridge 收到后 JSON 解析失败，直接关闭连接。

### 根因 B（次级阻断）：raceConnect 并发语义错误

`withThrowingTaskGroup` + `for try await` 语义上"第一个抛错子任务终止循环"。5G 下本地连接先超时，远程连接被取消。

### 4.1 go-bridge：精准兼容前导探活 + 双分支 session lookup + nil 判空

**文件**: `go-bridge/pairing_handler.go`

```go
func handlePairingWebSocket(w http.ResponseWriter, r *http.Request) {
    conn, err := pairingUpgrader.Upgrade(w, r, nil)
    if err != nil { return }
    defer conn.Close()

    const maxIgnoredProbes = 2
    ignoredCount := 0

    var acceptedPairingID string
    var acceptedManualCode string
    var acceptedDevice struct {
        DeviceID    string `json:"deviceId"`
        DisplayName string `json:"displayName"`
        Platform    string `json:"platform"`
    }

    for {
        _, message, err := conn.ReadMessage()
        if err != nil { return }

        if string(message) == "ping" && ignoredCount < maxIgnoredProbes {
            ignoredCount++
            slog.Debug("pairing: ignoring probe ping")
            continue
        }

        var claim struct {
            Type       string `json:"type"`
            PairingID  string `json:"pairingId"`
            ManualCode string `json:"manualCode"`
            Device     struct {
                DeviceID    string `json:"deviceId"`
                DisplayName string `json:"displayName"`
                Platform    string `json:"platform"`
            } `json:"device"`
        }

        if err := json.Unmarshal(message, &claim); err != nil {
            sendPairingResult(conn, false, "invalid message format")
            return
        }
        if claim.Type != "pairing_claim" {
            sendPairingResult(conn, false, "expected pairing_claim message")
            return
        }

        acceptedPairingID = claim.PairingID
        acceptedManualCode = claim.ManualCode
        acceptedDevice = claim.Device
        break
    }

    var session *PairingSession
    if acceptedPairingID != "" {
        session, err = globalPairingStore.Get(acceptedPairingID)
    } else if acceptedManualCode != "" {
        session, err = globalPairingStore.GetByManualCode(acceptedManualCode)
    } else {
        sendPairingResult(conn, false, "pairingId 或 manualCode 必须提供其一")
        return
    }
    if err != nil {
        sendPairingResult(conn, false, "pairing session lookup failed")
        return
    }
    if session == nil {
        sendPairingResult(conn, false, "pairing session not found")
        return
    }

    // ... 后续 session.Claim / 等待批准流程不变
```

### 4.2 iOS：移除应用层 ping，用控制帧 ping + 失败路径显式关闭

**文件**: `OpenCodeiOS/OpenCodeiOS/Services/Bridge/BridgePairingClient.swift`

```swift
private func sendWebSocketPing(task: URLSessionWebSocketTask) async throws {
    try await withCheckedThrowingContinuation { (continuation: CheckedContinuation<Void, Error>) in
        task.sendPing { error in
            if let error {
                continuation.resume(throwing: error)
            } else {
                continuation.resume(returning: ())
            }
        }
    }
}

private func connectWebSocketWithTimeout(url: URL) async throws -> URLSessionWebSocketTask {
    let task = sharedSession.webSocketTask(with: url)
    task.resume()

    do {
        try await withThrowingTaskGroup(of: Void.self) { group in
            group.addTask {
                try await self.sendWebSocketPing(task: task)
            }
            group.addTask {
                try await Task.sleep(nanoseconds: 8_000_000_000)
                throw PairingClientError.timeout
            }
            _ = try await group.next()
            group.cancelAll()
        }
        return task
    } catch {
        task.cancel(with: .goingAway, reason: nil)
        throw error
    }
}
```

### 4.3 iOS：重写 raceConnect — first success wins + 确定性错误选取 + success loser 清理

**文件**: `OpenCodeiOS/OpenCodeiOS/Services/Bridge/BridgePairingClient.swift`

设计目标：
1. 先成功的连接尽快返回（race 语义）
2. 失败的连接在 `connectWebSocketWithTimeout` 的 catch 中已关闭
3. 成功但未被选中的 loser 通过共享存储 + 显式 cancel 清理
4. 两个都失败时，按固定优先级确定性选取错误（远程 > 本地 > timeout）

```swift
private enum ConnectCandidate: String {
    case local
    case remote
}

private enum ConnectResult {
    case success(candidate: ConnectCandidate, task: URLSessionWebSocketTask)
    case failure(candidate: ConnectCandidate, error: Error)
}

/// Actor 隔离的共享存储，记录每个 candidate 已成功创建的 task。
/// winner 选定后从中取出 loser 的 task 显式关闭。
private actor ConnectTaskStore {
    private var tasks: [ConnectCandidate: URLSessionWebSocketTask] = [:]

    func store(_ task: URLSessionWebSocketTask, for candidate: ConnectCandidate) {
        tasks[candidate] = task
    }

    func take(for candidate: ConnectCandidate) -> URLSessionWebSocketTask? {
        tasks.removeValue(forKey: candidate)
    }
}

private func raceConnect(localURL: URL, remoteURL: URL) async throws -> URLSessionWebSocketTask {
    let store = ConnectTaskStore()

    let finalResult: ConnectResult = await withTaskGroup(of: ConnectResult.self) { group in

        group.addTask {
            do {
                NSLog("[PairingClient] 尝试本地配对: %@", localURL.absoluteString)
                let task = try await self.connectWebSocketWithTimeout(url: localURL)
                await store.store(task, for: .local)
                return .success(candidate: .local, task: task)
            } catch {
                NSLog("[PairingClient] 本地配对失败: %@", error.localizedDescription)
                return .failure(candidate: .local, error: error)
            }
        }

        group.addTask {
            do {
                NSLog("[PairingClient] 尝试远程配对: %@", remoteURL.absoluteString)
                let task = try await self.connectWebSocketWithTimeout(url: remoteURL)
                await store.store(task, for: .remote)
                return .success(candidate: .remote, task: task)
            } catch {
                NSLog("[PairingClient] 远程配对失败: %@", error.localizedDescription)
                return .failure(candidate: .remote, error: error)
            }
        }

        // first success wins：收到第一个 success 立即返回
        // 收到 failure 继续等另一个
        // 按 candidate 分开记录错误，用于确定性选取
        var localError: Error?
        var remoteError: Error?

        for await partial in group {
            switch partial {
            case .success:
                group.cancelAll()
                return partial
            case .failure(let candidate, let error):
                switch candidate {
                case .local:  localError = error
                case .remote: remoteError = error
                }
            }
        }

        // 两个都失败：确定性选取 — 远程 > 本地 > timeout
        let chosen: Error
        if let remoteError {
            chosen = remoteError
        } else if let localError {
            chosen = localError
        } else {
            chosen = PairingClientError.timeout
        }
        if remoteError != nil {
            return .failure(candidate: .remote, error: chosen)
        } else {
            return .failure(candidate: .local, error: chosen)
        }
    }

    switch finalResult {
    case .success(let winner, let task):
        // 清理 success loser
        let loser: ConnectCandidate = (winner == .local) ? .remote : .local
        if let loserTask = await store.take(for: loser) {
            NSLog("[PairingClient] 清理 success loser: %@", loser.rawValue)
            loserTask.cancel(with: .goingAway, reason: nil)
        }
        return task

    case .failure(_, let error):
        throw error
    }
}
```

**清理路径完整性**：

| 路径 | 清理方式 |
|------|---------|
| 连接超时 / ping 失败 | `connectWebSocketWithTimeout` catch 中 `task.cancel` |
| 成功但未被选为 winner | `raceConnect` 从 actor store 取出后 `task.cancel(with: .goingAway)` |
| 被取消的子任务 | `URLSessionWebSocketTask` 在 `cancel` 后自动中断连接 |

**时延行为**：

| 场景 | 行为 |
|------|------|
| 本地 0.3s 成功，远程 8s 超时 | 0.3s 返回本地成功（不等远程） |
| 远程 1s 成功，本地 5s 超时 | 1s 返回远程成功（不等本地） |
| 两个都成功 | 第一个成功的立即返回，另一个从 actor store 清理 |
| 两个都失败 | 等最后一个失败后，按远程 > 本地 > timeout 确定性选取 |

**并发安全说明**：

`ConnectTaskStore` 是 Swift actor，所有读写操作自动串行化，无需手动加锁。写入由子任务通过 `await store.store()` 完成，读取由 raceConnect 主逻辑在 group 结束后通过 `await store.take()` 完成。actor 保证不会出现并发读写。

### 6.1 go-bridge 回归测试

```
- 前导 "ping" 后发送 pairing_claim → 应成功
- 非法 JSON → 应返回明确错误
- pairing session 不存在 → 应返回明确错误，不 panic
- pairingID 为空时走 manualCode 分支 → 手动码配对正常
- claim 不残留旧字段
```

### 6.2 iOS 连接策略测试

```
- 本地先成功、远程后超时 → 应在本地成功时立即返回（约 0.3s）
- 远程先成功、本地后超时 → 应在远程成功时立即返回（约 1s）
- 本地失败、远程成功 → 返回远程成功
- 两个都失败 → 确定性选取错误（远程 > 本地 > timeout），不受调度顺序影响
- 成功但未被选中的 task → 被从 actor store 取出后显式 cancel
- 失败路径的 task → 被 connectWebSocketWithTimeout catch 显式 cancel
- 不发送应用层 "ping"
- .connecting 状态有 spinner
```
