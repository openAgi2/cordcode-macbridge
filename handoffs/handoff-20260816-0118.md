## 5. Constraints (关键约束)

**① 计划必须符合 CordCode 初衷**（`/Users/jacklee/Projects/cordcode-ios/docs/[综合版对比]2026-08-04-t3code-vs-cordcode.md`，§0/§1/§6）：CordCode 是 Mac 端用户自有工具的 iOS 跨端延伸——**探测用户已装的 runtime、复用用户已配的 key/provider、零迁移、双向接力；没有 runtime 就如实「未启动」；永不自托管**（不建自有 event store 当真相、不造私有 session 体系、不要求用户为 MacBridge 单独配 key、不替用户安装/编译/下载任何东西）。DSH 侧已按此落地：探测链 `①PATH dsh-jsonrpc-agent → ②用户全局 npm dsh（第一公民）→ ③pip wheel → ④nvm → ⑤源码 checkout 仅 DSH_DEV_SOURCE_ROOT 显式 opt-in（dev-only）`；凭据链 `provider key > ~/.dsh/.credentials.yaml > ~/.dsh/.env`；会话写入用户 `~/.dsh/sessions`（dsh web 可见可续聊）。任何新改动偏离此形态（例如又想代装 runtime、造隔离存储、要求用户配置）= 方向错误，直接打回。

**② 不得违反 CLAUDE.md「Session Sync v2 架构路线护栏」十二条**（`/Users/jacklee/Projects/cordcode-ios/CLAUDE.md`/`AGENTS.md` 同一章）。与 DSH 直接相关的既定裁决：DSH 已按**声明制**正式迁移 SSV2（设计 §8 🟢 session_sync_v2，live-only admission = kernel 状态经既有 hydrate 事务/fence 原子达 ready）；因此——不许在 backend 未声明 v2 时服务投影；不许返回空壳快照（死会话无痕 → 诚实 `projection.not_found`）；iOS 不许任何裁判行为（不超时收口、不无 ownership 渲染补丁、不自动 legacy fallback）；ownership 只由显式 mode + backend capability + 连接协商决定；hydrate 与 live 同属 Kernel 事务域。修复历史教训见 `docs/2026-08-15-dsh-driver-implementation-completion-audit.md` §8 与 `docs/2026-08-16-dsh-live-only-projection-spec.md`。
